# Использование и конфигурация

## Команды и аргументы

После [установки](installation.md) и активации собственной `.venv`:

```bash
start-app --version
start-app --help
start-app check --catalog-dir examples/catalog-v2
start-app run --catalog-dir examples/catalog-v2 --dry-run
start-app run --catalog-dir examples/catalog-v2
```

`check` проверяет каждый ресурс в порядке каталога. `run --dry-run` выполняет
проверки и показывает нужные действия. `run` обслуживает ресурсы: по состоянию
выбирает `install` или `repair` и проверяет результат. В версии 1.0.0 это
обслуживание окружения, а не команда запуска обслуживаемого приложения.

| Аргумент | Назначение |
|---|---|
| `check` или `run` | Обязательная операция при рабочем запуске |
| `--catalog-dir PATH` | Обязательный каталог с `catalog.json` |
| `--values PATH` | JSON-объект значений параметров; можно указать несколько файлов |
| `--set NAME=VALUE` | Явное значение объявленного параметра; повторяется для разных имён |
| `--dry-run` | Проверка и план действий без выполнения изменений |
| `-h`, `--help` | Справка без обязательных рабочих аргументов |
| `--version` | Версия без обязательных рабочих аргументов |

Все пути, имена и команды предметных действий задаются выбранным каталогом.
В поставляемом [примере](../examples/catalog-v2/catalog.json) один ресурс `example`
с действием `probe.py`, сообщающим `satisfied`. Это пример протокола, а не
профиль инфраструктуры ERP или Poise.

## Формат каталога и значения

Каноническое описание полей находится в README:
[каталог v2](../README.md#каталог-v2), [параметры](../README.md#параметры),
[состояния](../README.md#состояния-и-действия),
[протокол действия и коды](../README.md#протокол-действия).

Каждый ресурс объявляет `id`, `check`, `install`, `repair`. Действие содержит
массив `argv`, `cwd`, объект `env`, ожидаемую схему `output`,
`max_output_bytes` и `execution_bound_seconds`. Оператор предоставляет исполняемые
инструменты и выбирает ограничения, соответствующие этим инструментам.

Имена параметров объявляются в `parameters`; тип — `string`, `integer`, `number`
или `boolean`. Значение берётся из `default`, затем из объединённых `--values`
слева направо, затем из явно сопоставленной переменной окружения, затем из
`--set`. Наибольший приоритет имеет `--set`; каждое имя в нём задаётся один раз.
Для чисел и булевых значений используется JSON-запись; строка может быть обычным
текстом или JSON-строкой. Например, для каталога с объявленными параметрами
`host` типа `string` и `port` типа `integer`:

```bash
start-app check --catalog-dir /absolute/path/to/catalog \
  --values /absolute/path/to/site-values.json \
  --set 'host=127.0.0.1' \
  --set 'port=8080'
```

Пример содержимого `site-values.json`:

```json
{
  "host": "localhost",
  "port": 8000
}
```

Подстановка `${name}` однократная; значение, пришедшее из параметра, повторно
как шаблон не разбирается. `secret: true` скрывает значение в публичном результате;
для секретных параметров используйте объявленные переменные окружения, а не CLI.

## Пути и окружение

`--catalog-dir` и пути `--values` относительны к cwd вызывающего процесса.
Относительный `cwd` каждого действия считается от выбранного каталога.
Первый элемент `argv` выбирает исполняемый файл; остальные являются отдельными
аргументами, включая аргументы с пробелами. Shell-обработка строки не применяется.

`inherit_env` задаёт разрешённые переменные окружения, затем применяются значения
из `env` действия. Например, поставляемому `python3 probe.py check` нужен Python
в `PATH`, и пример явно наследует `PATH`. Выбирайте полный путь к инструменту
или обеспечьте подходящий `PATH` через каталог.

## Результат и повторный запуск

Итоговый JSON схемы `environment-maintenance/result/v2` поступает в stdout.
Он содержит результаты ресурсов и фактические вызовы, их stdout/stderr,
коды завершения и диагностику. Код 0 означает `ready`, 2 — `action_required`
или ошибку входа, 3 — `unavailable`, 4 — `failed`. Ошибка входа поступает в stderr
с пустым stdout. Формат ответов внешнего инструмента строго задан
[протоколом](../README.md#протокол-действия).

При `unavailable` выполните рекомендации результата. При ошибке протокола
прочитайте `invocation`, `error`, `timed_out`, `capture_complete` и потоки действия,
исправьте его настройку или реализацию. После попытки изменения прочитайте
`final_check` и фактическое состояние ресурса: изменение могло уже произойти.
Повторный `run` выбирайте после этой проверки. Полная процедура:
[отказ и восстановление](../README.md#отказ-и-восстановление).
