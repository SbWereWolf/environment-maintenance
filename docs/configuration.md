# Использование и конфигурация

## Команды и аргументы

[Пошаговая инструкция CLI](#пошаговая-инструкция-cli).

| Команда | Назначение | Применимые переопределения |
|---|---|---|
| `infra`, `deps`, `adjust` | Объявленное обслуживание | `--config`, `--parameters`, `--base-dir`, `--requirements` |
| `check` | Presence/availability/связанные условия | `--config`, `--parameters`, `--base-dir` |
| `run` | Запуск с учётом PGID | `--config`, `--parameters`, `--base-dir`, `--env`, `--app` |
| `run list` | Именованные записи требуемых ресурсов APP | `--config`, `--parameters`, `--base-dir`, `--env` |
| `stop`, `stop list`, `stop all` | Просмотр/остановка сохранённых групп | `--env`, `--app` по формам ниже |

Для всех шести команд и форм list/all доступна общая опция [`--output [FORMAT]`](#формат-json).

`-h`/`--help` и `--version` доступны без исполнения рабочих действий. Неизвестные аргументы предупреждаются в stderr и пропускаются; они не создают дополнительный режим. Используйте перечисленные флаги. Прежний `--dry-run` не обеспечивает preview.

`--requirements` принимает `all` либо JSON-массив уникальных строковых IDs. Без него infra/deps/adjust выбирают все записи. Повтор ID в selection или документе отвергает весь запрос до команд; неизвестный CLI ID предупреждается и пропускается. Порядок выбранных IDs сохраняется. У [SDK](configuration-reading.md#публичный-договор) неизвестный ID — ошибка.

Main по умолчанию — `CWD/start-app.json`. Относительные paths в `operations` и `invocation` считаются от main, явные CLI paths — от cwd. [Профиль](persistent-entry.md#поля-постоянного-профиля) задаёт parameters/base_dir; полностью явному вызову invocation не нужен. `base_dir` — абсолютная база cwd внешних команд.

## Формат JSON

Опция `--output [FORMAT]` меняет представление JSON-ответа текущего вызова:

| Вызов | Формат |
|---|---|
| Без `--output` | `one-line`: компактный JSON в одной строке |
| `--output` без значения | `pretty`: JSON с отступами в два пробела |
| `--output pretty` | `pretty` |
| `--output one-line` | `one-line` |

В обоих форматах сохраняются значения, порядок полей и экранирование Unicode через `\u…`; после JSON добавляется один перевод строки. Форматирование применяется к уже подготовленному результату CLI. Значения SDK, base64 содержимого команд и конфигурация `invocation` сохраняют свой договор; поля профиля для `output` нет.

Опцию разбирает стандартный `argparse`. Она допустима перед командой, после команды и после действия list/all. Примеры просмотра из каталога с подготовленным профилем:

```bash
start-app --output pretty run list
start-app run --output pretty list
start-app run list --output
start-app run list --output one-line
start-app run list --output --config /absolute/path/to/project/start-app.json
```

Следующий токен, который не является опцией, считается значением `--output`. Поэтому перед командой указывайте формат явно: `start-app --output check` разбирает `check` как недопустимый формат, затем сообщает об отсутствии команды и заканчивается с exit2 без действий. Опция перед следующим флагом, как в последнем примере, остаётся без значения и выбирает `pretty`.

При повторении опции на одном уровне действует последнее значение; опция после команды заменяет значение перед командой. Каждое неверное значение всё равно даёт предупреждение, даже если позднее задан корректный формат. Недопустимое значение выбирает `one-line`; это предупреждение само по себе не отменяет допустимую операцию.

## Предупреждения аргументов

Синтаксис и значения, проверяемые по самим аргументам, разбираются до чтения профиля, конфигов и выполнения действий. Сразу после разбора предупреждения выводятся в stderr с префиксом `Предупреждение:`.

| Ситуация | Продолжение |
|---|---|
| Неверный формат `--output` | Предупреждение и `one-line`; допустимая операция выполняется |
| Неизвестные аргументы | Предупреждение, пропуск неизвестных аргументов и выполнение допустимой операции |
| Отсутствующая/неизвестная команда, отсутствующее обязательное значение флага | Предупреждение, exit2, без чтения конфигов и действий |
| Недопустимое имя `--env`, `stop --app` без `--env` | Предупреждение, exit2, без чтения конфигов и действий |
| Неверный JSON/тип/повтор ID в `--requirements` | Предупреждение, exit2, без чтения конфигов и действий |

Например, `start-app run list --output yaml` предупреждает о формате, затем выполняет просмотр с компактным JSON. Для `--requirements` подходят `all` или массив уникальных строк; JSON-строка `"all"` массивом не является.

Проверки существования файлов, состава документов, наличия запрошенных IDs и доступности ресурсов требуют соответствующих входов и выполняются позднее их владельцами. Дубликат в самом документе отвергается при чтении; неизвестный CLI ID предупреждается и пропускается после чтения документа, тогда как SDK остаётся строгим. Это не ранние предупреждения парсера. Предупреждение не является режимом проверки без эффектов: прежде чем повторять рабочую операцию, учитывайте её фактический результат.

`--help` и `--version` сохраняют текстовый вывод без рабочих действий; `--output` не превращает их в JSON. Ранний отказ с exit2 может содержать только stderr и пустой stdout. Ошибки чтения конфигурации и операционные результаты сохраняют свои существующие формы: форматирование применяется, когда CLI действительно возвращает JSON, и не создаёт JSON-оболочку для stderr.

## Пошаговая инструкция CLI

Сначала [подготовьте профиль](persistent-entry.md#пошаговая-инструкция). В каталоге приложения:

```bash
start-app --version
start-app --help
start-app infra
start-app deps
start-app adjust
start-app check
start-app run list
```

Ресурсы и допустимый порядок обслуживания задаёт приложение. Для требования `assets` вашего infra документа:

```bash
start-app infra --requirements '["assets"]'
```

`[]` выбирает пустой список, `["all"]` — буквальный ID `all`.

## Именованные run и stop

Ниже альтернативные формы, а не обязательная последовательность:

| Форма | Результат |
|---|---|
| `run` | Все APP в новой UUID-среде |
| `run --env ENV` | Все APP в именованной среде |
| `run --app APP` | Один APP в новой UUID-среде |
| `run --env ENV --app APP` | Один новый APP в этой среде |
| `run list` | Карта APP: `pgid: null` и требуемые ресурсы |
| `run list --env ENV` | Такая же карта для APP, ещё не зарегистрированных в найденной ENV |
| `stop` или `stop list` | Просмотр всех запусков с PGID и сохранёнными ресурсами |
| `stop list --env ENV` | Просмотр указанной ENV |
| `stop --env ENV` | SIGTERM всем сохранённым группам ENV |
| `stop --env ENV --app APP` | SIGTERM одному APP |
| `stop all` | SIGTERM всем группам всех читаемых ENV |

Для stop выбор APP требует ENV. `APP=all` — буквальный ID; для всех APP опускают `--app`. Имя ENV `all` зарезервировано; используйте, например, `dev-1`. Полные правила и [пример](process-launch.md#пошаговая-инструкция) принадлежат [договору процессов](process-launch.md#запуск-процессов). Stop читает сохранённый реестр OS temp, а не main/parameters.

Ресурсы и полные примеры ответов описаны [в договоре процессов](process-launch.md#ресурсы-приложения). При наличии `resources` просмотр использует тот же выбранный профиль/parameters/base-dir, что и запуск; для отсутствующей ENV возвращает `applications: {}` и `found: false`. SDK-списки ID сохраняют прежний договор.

## Результат и повторный запуск

JSON-ответ выводится полностью в [выбранном формате](#формат-json); stdout/stderr команд передаётся в base64 по [договору transport](action-execution.md#итог-исполнения). У run/stop успех даёт exit0, операционный отказ — exit1, ошибки аргументов/входов — exit2. У run при допустимом имени ENV входная ошибка сохраняет JSON с адресом и деталями; ранний отказ аргументов ограничивается stderr, поздний отказ разрешения конфигурации также может содержать только stderr. Подготовка/check имеют собственные [подробности результата](resource-preparation.md#результат-и-диагностика).

Повтор — новое явное действие. Сначала прочитайте полный результат и фактические эффекты. Для частичного запуска используйте `run list --env ENV` и точный APP. [Восстановление](migration-v4.md#ручное-восстановление) сохраняет остальные приложения и записи.
