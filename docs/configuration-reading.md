# Чтение требований конфигурации

## Библиотека чтения

[Пошаговая инструкция всех операций](#пошаговая-инструкция).

Библиотека доступна начиная с npm-поставки 4.0.0, в собственном Python пакета и его исходниках; этот договор сохраняется в 5.0.0.
[Установка и контекст примеров](npm-distribution.md#библиотека-и-поставленные-примеры)
объясняют выбор runtime и каталога. Исторический wheel 1.0.0 остаётся отдельной
поставкой. Примеры ниже явно выбирают `src` выбранного исходного набора, который
может находиться внутри установленного npm-пакета.

Это чтение данных для внешних инструментов. Оно не запускает команды ресурсов,
не рендерит параметры и не изменяет конфиги. CLI описан в [справочнике](configuration.md#команды-и-аргументы), check — в [договоре проверки](resource-checking.md#проверка-окружения).

## Публичный договор

Обе функции импортируются из `environment_maintenance`.

| Функция | Аргументы | Результат |
|---|---|---|
| `list_requirement_ids(config_path, operation)` | Явный путь к главному файлу и имя операции | Только список строковых идентификаторов в порядке документа |
| `read_requirements(config_path, operation, selection)` | Тот же путь, операция и массив IDs либо строка `"all"` | Список полных объектов требований |

`config_path` принимает строку или `pathlib.Path`. `operation` — имя из
сопоставления `operations`, а не встроенный список допустимых имён.
Относительный путь сопоставленного файла считается от каталога главного файла;
явно заданный абсолютный путь используется непосредственно.

Массив `selection` сохраняет запрошенный порядок уникальных IDs. Повтор ID в selection или документе вызывает ValueError до эффектов. Пустой массив
возвращает `[]`. Строка `"all"` возвращает все объекты в порядке документа.
Список `["all"]` выбирает обычный ресурс с ID `all`, когда такой ID объявлен.
Пустой выбранный массив (`applications` для run, `requirements` для остальных) допустим: IDs, пустая выборка и `all` возвращают `[]`.

Неизвестный ID вызывает `ValueError`, а не частичный успешный результат.
Объекты возвращаются целиком, включая дополнительные вложенные поля и буквальные
placeholders. Они отделены от внутреннего состояния: изменение возвращённого
объекта не изменяет файл или следующее чтение. Каждый вызов заново читает главный
и выбранный документы, поэтому видит изменения, сохранённые их внешним владельцем.

У operation `run` эти функции сохраняют тот же договор: `list_requirement_ids` возвращает ID, `read_requirements` — полные объекты с буквальным `resources` и неразвёрнутыми шаблонами. Они не определяют формат CLI `run list`, который [разрешает ресурсы в выбранном контексте](process-launch.md#ресурсы-приложения). API доступен с 4.0.0 и сохраняется в 5.0.0.

## Формат конфигов

Главный UTF-8 JSON-файл содержит объект `operations`: имя операции → непустая
строка пути к конфигу. Реальный пример:
[app.example.json](../examples/configuration-reading/app.example.json).
Операции `infra` и `deps` выбраны в данных примера; `custom-check` показывает
пользовательское имя с тем же механизмом чтения.

Выбранный UTF-8 JSON-файл operation `run` содержит массив `applications`; остальные операции, включая custom names, — `requirements`. Его члены —
объекты с уникальным непустым строковым `id`. Остальные поля являются данными
конкретного внешнего инструмента и возвращаются без преобразования. Для чтения
не требуется планировать или выполнять содержащиеся в данных команды.

Примеры одной схемы: [infra](../examples/configuration-reading/infra.example.json)
и [deps](../examples/configuration-reading/deps.example.json). Дополнительные
поля верхнего уровня чтению не мешают; файлы не переписываются. Рабочие конфиги
выбираются явно и исключаются из Git их владельцем; отслеживаемые `*.example.json`
здесь содержат только демонстрационные значения, не данные развёртывания.

## Пошаговая инструкция

Из корня исходников с данным API выберите подготовленный Python 3.11+:

```bash
: "${app_python:?Выберите Python по npm-инструкции или подготовке разработчика}"
```

Подставьте фактический путь. В дочерней рабочей копии это может быть уже
подготовленный интерпретатор приложения; его переустановка не нужна.
Следующие команды явно загружают `src` текущего checkout через `PYTHONPATH`.
Они читают примеры и не требуют работающих PostgreSQL, Redis или Composer.

### Получить идентификаторы

```bash
PYTHONPATH=src "$app_python" -B - <<'PY'
import json
from environment_maintenance import list_requirement_ids
print(json.dumps(list_requirement_ids("examples/configuration-reading/app.example.json", "infra")))
PY
```

Ожидается JSON `["postgres", "redis"]`.

### Прочитать выбранные полные объекты

```bash
PYTHONPATH=src "$app_python" -B - <<'PY'
import json
from environment_maintenance import read_requirements
print(json.dumps(read_requirements("examples/configuration-reading/app.example.json", "infra", ["redis"]), ensure_ascii=False))
PY
```

Ожидается только выбранный полный объект:

```json
[{"id": "redis", "connection": {"host": "127.0.0.1", "port": 6379}, "label": "Кеш"}]
```

Для упорядоченного пакетного запроса передайте, например,
`["redis", "postgres"]`: получите два полных объекта в этом порядке. Повторяющийся ID предварительно исправляется в selection.

### Прочитать весь список

```bash
PYTHONPATH=src "$app_python" -B - <<'PY'
import json
from environment_maintenance import read_requirements
print(json.dumps(read_requirements("examples/configuration-reading/app.example.json", "infra", "all"), ensure_ascii=False))
PY
```

Полный результат:

```json
[{"id": "postgres", "connection": {"host": "127.0.0.1", "port": 5432}}, {"id": "redis", "connection": {"host": "127.0.0.1", "port": 6379}, "label": "Кеш"}]
```

### Выбрать другой конфиг

```bash
PYTHONPATH=src "$app_python" -B - <<'PY'
import json
from environment_maintenance import list_requirement_ids, read_requirements
config = "examples/configuration-reading/app.example.json"
print(json.dumps(read_requirements(config, "deps", "all")))
print(json.dumps(list_requirement_ids(config, "custom-check")))
PY
```

Первая строка:

```json
[{"id": "php-vendor", "details": {"directory": "vendor", "manager": "composer"}}]
```

Вторая строка — `["postgres", "redis"]`. Имя операции выбрало другой документ
либо пользовательское сопоставление; правило чтения осталось тем же.

### Использовать абсолютный путь

Пример создаёт собственный временный главный файл, не изменяя исходные примеры:

```bash
PYTHONPATH=src "$app_python" -B - <<'PY'
import json
from pathlib import Path
from tempfile import TemporaryDirectory
from environment_maintenance import list_requirement_ids
selected = Path("examples/configuration-reading/infra.example.json").absolute()
with TemporaryDirectory(prefix="reader-example-", dir=".") as temporary:
    main = Path(temporary) / "app.json"
    main.write_text(json.dumps({"operations": {"chosen": str(selected)}}), encoding="utf-8")
    print(json.dumps(list_requirement_ids(main, "chosen")))
PY
```

Ожидается `["postgres", "redis"]`; временный файл удаляется при выходе из блока.

## Диагностика и повторное чтение

Функции возвращают обычные значения Python или выбрасывают `ValueError`.
Ошибки файла/UTF-8/JSON содержат выбранный путь; ошибки известных полей —
соответствующее поле, операцию или ID.

1. Прочитайте контекст исключения и определите главный либо выбранный документ.
2. Сверьте его с форматом выше и сохраните правильные данные внешним инструментом,
   который владеет этим конфигом.
3. Повторите тот же вызов: он читает актуальные файлы без дополнительного сброса.

Здесь нет повторного запуска побочного действия: библиотека только читает данные.
Изменение файлов доступно через [библиотеку записи](configuration-editing.md#библиотека-записи),
а подготовка ресурсов и запуск процессов — инструментам соответствующих операций.

## Собственный внешний инструмент

[Правильные вызовы библиотеки](#пошаговая-инструкция) показывают её границу.
Инструмент сначала получает IDs, затем читает нужные объекты одним пакетным
вызовом; `all` используется, когда ему действительно нужны все объекты.
Дальнейшее предметное действие реализует сам внешний инструмент.

Если имеющиеся инструменты не обеспечивают требуемого поведения, разработайте
собственный инструмент и подключите эту библиотеку для чтения конфигурации.
Для изменения используйте [четыре операции записи](configuration-editing.md#публичный-договор)
и их [корректные примеры](configuration-editing.md#пошаговая-инструкция).
Само наличие библиотеки не создаёт обработчик установки, настройки или запуска.
Для объявленных цепочек уже реализована [библиотека исполнения](action-execution.md#библиотека-исполнения)
с [пошаговой инструкцией](action-execution.md#пошаговая-инструкция).
Новые команды CLI и новая пакетная поставка остаются отдельными возможностями;
чтение и библиотечный CRUD продолжают работать только с данными.
