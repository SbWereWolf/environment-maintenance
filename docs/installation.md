# Установка самостоятельного приложения

## Условия

Команды ниже выполняются в Bash на Linux/POSIX, в том числе Ubuntu WSL2.
Нужен Python 3.11 или новее с модулями `venv` и `pip`; проверенная среда — Python
3.12.3. Действия выбранного каталога имеют собственные зависимости, например
`python3` в `PATH` для поставляемого примера. Их обеспечивает оператор окружения.

У приложения собственный каталог, например
`/home/sbwerewolf/workdata/environment-maintenance`. Все его исходники, документация,
тесты, `.venv`, сборки и журналы экземпляра находятся под этим корнем.
Обслуживаемые ресурсы и выбранные оператором каталоги — внешние входы приложения,
а не часть его установки. Установленный wheel работает без исходников Poise,
его БД, конфигурации и прежнего checkout `environment-maintenance-repair`.

## Установка из исходников

Этот раздел описывает выпущенный 1.0.0. Откройте checkout выбранного релизного
tag `v1.0.0` либо распакованный исходный архив
`environment_maintenance-1.0.0.tar.gz`. Следующие команды выполняются из его корня:

```bash
python3 -m venv --copies .venv
.venv/bin/python -m pip install .
./start-app --version
./start-app check --catalog-dir examples/catalog-v2
```

`pip install .` использует стандартный сборщик из `pyproject.toml`; при обычной
установке он получает необходимые средства сборки из настроенного Python-индекса.
Для установки без обращения к индексу используйте готовый wheel по следующему
разделу. Ожидаемая версия — `environment-maintenance 1.0.0`; пример каталога
возвращает JSON с `status: ready` и код 0.

Разработка 2.0 в текущем `master` уже содержит новые библиотечные возможности
и runtime-зависимости; она не является неизменным исходным архивом 1.0.0.
Для проверки таких исходников используйте
[подготовку разработчика](development.md#подготовка) и явный `PYTHONPATH=src`,
сохраняя установленный выпущенный экземпляр отдельно.

Корневой `start-app` использует только `.venv/bin/python` рядом с собой и запускает
установленный пакет, а не исходники через `PYTHONPATH`. Поэтому изменение исходников
требует повторной установки. Диагностика отсутствующего локального Python означает,
что нужно выполнить создание окружения и установку по этой инструкции.

## Установка готового wheel

Для выпущенного wheel 1.0.0 без сторонних runtime-зависимостей сверьте SHA-256
с квитанцией поставки. В собственном каталоге
экземпляра создайте `.venv` и установите этот файл; путь в команде замените путём
к выбранному комплекту:

```bash
python3 -m venv --copies .venv
.venv/bin/python -m pip install --no-index --no-deps \
  /absolute/path/to/release/environment_maintenance-1.0.0-py3-none-any.whl
.venv/bin/start-app --version
.venv/bin/start-app --help
```

Wheel содержит пакет и стандартные консольные входы, а исходный архив дополнительно
содержит корневой `start-app`, документацию, примеры и тесты. После установки
активируйте собственное окружение для короткой команды:

```bash
. .venv/bin/activate
start-app --version
```

Команда `environment-maintenance` остаётся вторым именем того же CLI.
Готовые `.venv` между корнями не переносятся: создавайте окружение в месте
установки и устанавливайте выбранный wheel. Python и системные инструменты
устанавливаются отдельно; отсутствие Python-зависимостей релиза 1.0.0 не заменяет их.

## Пути и обновление

Корневой вход может быть вызван по абсолютному пути из другого рабочего каталога:

```bash
/home/sbwerewolf/workdata/environment-maintenance/start-app --version
/home/sbwerewolf/workdata/environment-maintenance/start-app check \
  --catalog-dir /home/sbwerewolf/workdata/environment-maintenance/examples/catalog-v2
```

Относительные `--catalog-dir` и `--values` считаются от текущего каталога
вызывающего процесса. Рабочие каталоги действий считаются от выбранного каталога
ресурсов, как описано в [конфигурации](configuration.md#пути-и-окружение).

Обновление — явная установка нового проверенного wheel в `.venv` выбранного
экземпляра с последующим `--version` и `check` по его каталогу. Старые потребители
прежних версий обновляются отдельно. Выбор каталога и рабочего окружения остаётся
за оператором; новая поставка сама их не изменяет.
