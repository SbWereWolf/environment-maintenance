# Установка самостоятельного приложения

[Договор npm-поставки](npm-distribution.md#пакетная-поставка-npm) содержит полную инструкцию установки выбранного экземпляра.

## Npm-поставка

Приложение выбирает конкретный tgz выбранного выпуска своей npm-зависимостью с package.json, npm-generated lock и собственным installed runtime. Глобальный prefix также поддерживается. Каждое независимое приложение выбирает и обновляет экземпляр отдельно; несколько регистраций одного приложения могут использовать его копию.

Для 5.1.1 требуется опубликованная зависимость `command-execution==1.0.0`; [отдельная инструкция](command-package.md#обновление-обслуживания-окружения) описывает установку из реестра, сохранение совместимых импортов и проверку каждого потребителя. При отсутствии этой версии в выбранном Python-индексе установка останавливается; сначала завершается самостоятельный выпуск библиотеки.

## Условия

Linux/POSIX, Node22+, npm10+, абсолютный Python3.11+ с venv/pip и доступ к выбранным build/runtime dependencies. Проверенная среда указана в [README](../README.md#supported-platform-and-checks). Writable prefix и индекс либо offline wheelhouse предоставляет владелец установки.

Python и `.venv` пакета принадлежат инструменту. Python/Node/PHP приложения, терминал, display и команды обслуживания принадлежат приложению. Установка пакета не развёртывает внешние ресурсы.

## Первоначальное развёртывание системы приложений

Внешний EM — средство развёртывания и полного удаления системы, а не
инфраструктурная зависимость её приложений или тестов.

| Этап | Какая установка EM выполняет работу |
|---|---|
| Первоначальное развёртывание | Внешняя: выполняет декларации владельца системы, подготавливает окружение и устанавливает внутренний EM. |
| Дальнейшее обслуживание | Внутренняя, установленная в системе: выполняет последующие `infra`, `deps`, `adjust`, `check`, `run`, `run list`, `stop` и `stop list`. |
| Полное удаление системы | Внешняя: выполняет предоставленный владельцем системы сценарий удаления, включая удаление внутреннего EM. |

После развёртывания приложения и их тесты работают на собственной
инфраструктуре системы. Доступность внешней установки EM для их работы
и дальнейшего обслуживания не требуется. Внутренний EM устанавливается
как [собственная зависимость приложения](npm-distribution.md#собственная-зависимость-приложения).

Для полного удаления внешняя установка EM остаётся вне удаляемой
системы. Состав удаляемых ресурсов и действия удаления задаёт владелец
системы в её декларациях обслуживания.

## Установка из исходников

Выберите точные исходники 5.1.1 и доступ к выбранному wheel библиотеки 1.0.0 и собственный каталог установки. Из их корня:

```bash
python3 -m venv --copies .venv
.venv/bin/python -m pip install .
./start-app --version
./start-app --help
```

Корневой entry использует соседний установленный Python с `-I`, сохраняя cwd вызывающего приложения. Изменение source требует явной переустановки выбранных байтов владельцем окружения.

## Установка готового wheel

Из подготовленного Python с pip в своём окружении и с доступным выбранным набором зависимостей:

```bash
/absolute/path/to/venv/bin/python -m pip install \
  /absolute/path/to/environment_maintenance-5.1.1-py3-none-any.whl
/absolute/path/to/venv/bin/start-app --version
```

Pip разрешает зависимость `command-execution==1.0.0`; для offline-установки задайте `PIP_NO_INDEX=1` и `PIP_FIND_LINKS` на полный [wheelhouse](command-package.md#установка-выбранной-версии). Wheel содержит Python API и console entry. Для bundled docs/examples/skill и npm-границы выбирайте [npm-комплект](npm-distribution.md#пошаговая-инструкция).

## Пути и обновление

Permanent source, конфигурации и выбранная supply позволяют восстановить установленную копию после удаления disposable runtime. Единственный исходник нужного системе обработчика хранится в Git/выбранной поставке, а не только в `.runtime` или Task-root. Installed venv воспроизводится package manager.

Согласуйте version/archive/lock/config до обновления. Следуйте [миграции](migration-v5.md#переход-конфигурации): новый формат списков и декларации ресурсов переключаются вместе с зависимостью. Прежние выпуски сохраняют свои байты и документацию. Обновление одного экземпляра не обновляет другие; рабочие конфиги и данные сохраняет их владелец. Проверка кандидата не означает публикацию или внедрение.
